# История изменений

## Не выпущено

- Добавлен `export:sqlite`: пять аналитических профилей, фильтры корпуса/частей/полей,
  отдельные инструкции и review, provenance и отчёт о полноте; fixed manifest
  ready-ревизий, безопасная публикация одного SQLite без изменения источника.
  [Контракт и ограничения](docs/sqlite-export.md); production acceptance отдельно.
- Прогресс экспорта использует общий с sync однострочный renderer: spinner при
  неизвестном объёме, bar по фиксированному manifest, стадии проверки и публикации.
  Без TTY вывод ограничен по частоте; итоговый JSON в stdout остаётся чистым.
- SQLite-экспорт читает canonical-корпус одним native HTTP stream, без обязательных
  lookup indexes и повторных SQL-сканов по ревизиям. Curl и private OS FIFO
  ограничивают буферизацию; encrypted temporary spool группирует записи перед
  проекцией. Ошибки показывают стадию и безопасный код без приватного payload.
- Ускорена запись SQLite партиями без ослабления durability итогового файла;
  оптимизированы временный spool, разбор строк, справочники и большие turn-window.
  Добавлены фазовые timings и обязательная сверка записанного payload с pre-write
  digests, включая NULL, NUL и Unicode.
- Документация SQLite и встроенный `data_dictionary` дополнены маршрутом чтения
  для аналитика/LLM, правилами доказательного анализа и SQL для подсчётов,
  каталога тредов и проверки неоднозначностей. Существующие выгрузки не изменяются.
- Публичная история обезличена: личные отчёты и выборки удалены из Git,
  пути и тестовые данные заменены нейтральными примерами; `reports/` игнорируется.
  Из комментариев, документации и сообщений коммитов удалены реальные
  измерения и статистика; имена/email авторов и даты коммитов сохранены.
- Диагностические скрипты принимают явные пути и IDs вместо встроенных
  выборок. Targeted reparse отклоняет пустой список до доступа к БД.

## [0.1.0] — 2026-09-09

Первый релиз ai-baka — локального single-user CLI на Bun и TypeScript для
архивации и поиска по диалогам с AI-агентами. Этот выпуск фиксирует накопленную
функциональность проекта; установка — из исходников.

### Источники и архивирование

- Поддержаны восемь харнессов: OpenAI Codex (в том числе сессии в Orca),
  Claude Code, Claude Desktop, OpenCode, Cursor, Qwen Code, Kimi Code / Kimi CLI
  и Oh My Pi (OMP).
- Реализованы обнаружение установок и источников (`discover`), настройка
  source roots через окружение и инкрементальная синхронизация (`sync`)
  с фильтром по харнессу, предварительным просмотром и JSON-выводом.
- Исходники сохраняются как неизменяемые raw-снимки с полным SHA-256.
  SQLite снимается через `VACUUM INTO` с учётом WAL; каталоги сессий Kimi
  разбираются из сохранённых снимков.
- Сохраняются история ревизий и происхождение данных: машина, OS-аккаунт,
  харнесс, workspace и исходный диалог. Есть обработка переименований,
  исчезнувших источников и полных/частичных сканирований. Удаление исходника
  не удаляет архив; неполное сканирование не подтверждает удаление.
- Парсеры приводят сообщения, reasoning, вызовы и результаты инструментов,
  модели, reasoning effort и token usage к общей модели. Неизвестные события
  сохраняются, а неподдерживаемые служебные файлы не становятся поисковыми
  диалогами.
- Добавлен повторный разбор immutable raw (`reparse`), в том числе только
  устаревшими версиями парсеров, без обращения к живому источнику.
- Ускорен повторный sync: отдельный наблюдённый fingerprint источника с
  учётом SQLite WAL устраняет повторный `VACUUM INTO` неизменённых баз и
  повторные snapshots после изменения только mtime. Кэш удаляемый, raw
  identity и история revision не меняются. Добавлены reuse SHA физических
  дублей Codex/Orca, пропуск уже обработанной current file revision,
  пакетные presence updates и тайминги этапов `sync_timing`.
- Кэш sync сохраняется после каждого обработанного источника: прерывание
  позднее в запуске не заставляет заново переснимать уже проверенные SQLite.
- Обработка много-диалоговых баз показывает прогресс по диалогам; JSONL-журнал
  разделяет время чтения, подготовки identity и записи каждого диалога.
- Для всех harness'ов разделены повтор capture и повтор parse: стабильный
  raw переиспользуется при `partial`/`parse_error` и смене pipeline, не
  отменяя retry. Capture checkpoint сохраняется до долгой обработки диалогов.
  Убрано двойное чтение head hash при проверке source observation.
- Codex/Orca hardlink-дубли проверяются по стабильной физической identity
  без полного чтения файлов; SHA-индекс строится лениво только для отдельных
  копий. Сохранены проверки гонок и полного SHA для разных inode.
- Распознанный history-only индекс Claude Code без повреждённых строк
  архивируется без ложного `empty_snapshot` и бесконечного повторного разбора.

### Хранилище и ежедневная работа

- Реализованы SurrealDB repositories, миграции схемы, транзакционная запись
  диалогов и детерминированные идентификаторы для идемпотентной обработки.
  Для 0.1.0 все дорелизные изменения сведены в `schema/0001_initial.surql`
  (версия схемы 1), включая метаданные legacy-импорта, размеры контента,
  timing ответов и lineage дочерних сессий Codex. Новые миграции будут
  добавляться при переходе на следующие релизы; существующая дорелизная
  история миграций не перенумеровывается автоматически.
- SurrealDB 3.2.4 закреплена тегом и digest Docker image; RocksDB хранится
  отдельно от raw-архива. Compose открывает БД только на `127.0.0.1:8901`.
- Добавлены инициализация архива, проверка тома, прав и свободного места,
  process lock, управление БД (`db preflight|up|down|status|migrate|logs`)
  и безопасное извлечение диска на macOS (`disk eject`).
- `sync` умеет ограниченно ожидать готовность локальной БД и запускать Compose;
  на macOS — запускать установленный OrbStack или Docker Desktop по выбранному
  Docker endpoint. Доступная БД не перезапускается, Docker context не меняется.
- Интерактивный sync показывает прогресс и итоговую сводку замечаний;
  JSON-режим разделяет журнал событий в stderr и результат в stdout.

### Поиск и экспорт

- Добавлен локальный BM25-поиск (`search`) по реальным пользовательским
  сообщениям и финальным видимым ответам ассистента текущих ревизий,
  с подсветкой совпадений и фрагментами текста.
- Доступны фильтры по харнессу, машине, пользователю, workspace, вендору,
  модели, роли и датам. Длинные документы сегментируются с ограничением
  размера; поисковая проекция перестраивается из canonical corpus
  командой `search:rebuild`.
- Реализованы HNSW vector search и hybrid search с объединением BM25 и
  векторной выдачи через RRF, дедупликацией сообщений и ограничением числа
  результатов одного диалога. Без готового active embedding space или
  API-ключа hybrid переходит к текстовому поиску с предупреждением.
- `export-thread` выгружает диалог в canonical JSON без путей к исходникам
  по умолчанию. Текст сообщений при этом не анонимизируется.

### Эмбеддинги и оценка качества

- Реализованы OpenAI embedding provider, batch-запросы, retry/backoff,
  отдельные embedding spaces с HNSW-таблицами и очередь заданий с lease,
  проверкой размерности, идемпотентной записью и обнаружением stale jobs.
- Добавлены планирование объёма, точный подсчёт токенов через закреплённый
  tokenizer, оценка стоимости по заданному оператором тарифу, статусы,
  повтор ошибок, отмена заданий и перестроение устаревших векторов.
- Платная обработка разделена на ограниченные candidate runs и production
  backfill: нужны привязанные к данным планы и явные подтверждения.
  Общая команда `embeddings run` намеренно отключена.
- Реализованы privacy-фильтры перед отправкой документов провайдеру,
  сверка очередей и векторов с изменившейся политикой без вызова API,
  аудит jobs/vectors/HNSW и безопасное удаление отклонённых неактивных spaces.
- Добавлено сравнение BM25/vector/hybrid по размеченным запросам, а также
  full-corpus evaluation и отдельная процедура принятия результатов.
  Эмбеддинги не входят в критический путь sync: синхронизация может поставить
  задания в очередь, но сама не вызывает OpenAI.

### Диагностика, резервные копии и восстановление

- `status` показывает состояние архива и обслуживающих процедур;
  `validate` проверяет инварианты и связи; `raw:verify` сверяет наличие,
  размеры и SHA-256 raw-файлов. `doctor` по умолчанию только диагностирует,
  а исправления требуют явных разрешений.
- `backup` делает потоковый logical export с компрессией zstd либо gzip
  и атомарной записью manifest с контрольными суммами, количеством записей
  и hash raw manifest под process lock.
- `backup off-device plan|run|verify` планирует, копирует и проверяет
  переносимый backup bundle на другом устройстве.
- `restore:test` проверяет backup до импорта и восстанавливает его в отдельном
  временном контейнере закреплённой версии. Проверяются количества записей,
  ссылки, raw и BM25; FULLTEXT-индекс строится после загрузки данных.
  Процедура временно останавливает production и проверяет её после запуска.
- Реализованы аварийное логическое восстановление в свежее внутреннее
  хранилище (`recovery:rebuild`) и отдельное продвижение проверенного дерева
  (`recovery:promote`). Это операторские процедуры с проверками идентичности
  и подтверждениями, а не копирование или ремонт живой RocksDB на месте.

### Перенос legacy-архива

- Добавлены `migration plan|run|retry|status` для SQLite-архива прежнего baka:
  неизменяемый snapshot источника, preflight, импорт raw и canonical данных,
  сопоставление provenance, дедупликация и построчная reconciliation.
- Проблемные строки сохраняются в quarantine с audit trail и возможностью
  повторной обработки. Отдельный подписанный workflow позволяет принять
  строго определённые неустранимые исключения.
- Запись требует подписанных разрешений, host mapping и проверенных
  backup/restore artifacts. Legacy-архив остаётся read-only; dual-write нет.

### Исправления надёжности и качества данных

- Усилены fingerprint-проверки источников, атомарный process lock и обработка
  частичных снимков; ошибки разбора не оставляют ложную successful revision.
- Canonical hash учитывает метаданные сообщений, chunks и исходные usage
  events. Повторный успешный разбор закрывает прежние ingest errors.
- Исправлены классификация SQLite/JSON источников, снимки закрытых WAL-баз,
  дедупликация streaming-сообщений Claude Desktop и выделение финальных
  ответов в пределах соответствующего пользовательского turn.
- Исправлен повторный учёт Codex token usage из одинаковых rate-limit bucket
  событий и унаследованной длительности turn в дочерних rollout. Добавлены
  lineage-метаданные и скрипты анализа replay, usage и эффективности моделей.
- Длительные подключения обновляют авторизацию SurrealDB; фатальные ошибки
  CLI завершают процесс, не оставляя открытый WebSocket и удерживаемый lock.
- Multi-GiB restore использует потоковую загрузку native curl и конечный
  лимит HTTP import; глобальный FULLTEXT по историческим chunks удалён,
  сами canonical chunks и история сохранены.

### Ограничения и статус выпуска

- Это локальный CLI, не web-приложение, облачная служба или межкомпьютерная
  синхронизация. Основной проверенный сценарий — macOS; Linux и WSL2 имеют
  ограничения, нативный Windows не поддерживается проверкой хранилища.
- Архив требует отдельного смонтированного тома. Live RocksDB должна лежать
  на поддерживаемой внутренней файловой системе, не на ExFAT.
- Исторические ревизии, reasoning и tool-содержимое сохраняются, но не входят
  в обычный поисковый индекс. Legacy forensic flags отвергаются.
- Sync и BM25 работают без внешних API; генерация эмбеддингов и векторные
  запросы отправляют данные OpenAI. Raw, exports и отчёты могут содержать
  приватные сведения и не предназначены для публикации.
- Реализованный код legacy import, платного backfill и off-device backup
  не означает завершённую production-приёмку. Согласно плану, live migration,
  выбор production space, полный backfill, финальная оценка качества и cutover
  остаются отдельными операторскими этапами. Смена pin на SurrealDB 3.2.4
  также требует новой проверки restore и совместимости.
- Установка выполняется из исходников; `private: true` сохраняется для защиты
  от случайной публикации в npm и не мешает публикации репозитория на GitHub.
